# Checklist: antes de un release

- [ ] Todos los tests automatizados pasan en la rama a liberar.
- [ ] El changelog/notas de release reflejan los cambios reales incluidos.
- [ ] No quedan feature flags a medio activar sin decisión explícita.
- [ ] Se verificó el comportamiento en un entorno lo más parecido a producción posible.
- [ ] Hay un plan de rollback claro si algo falla post-release.
- [ ] Se avisó a quien corresponda (equipo, stakeholders) antes de liberar, si el cambio es visible o riesgoso.
