# Checklist: revisión de código

- [ ] Se entendió el propósito del cambio antes de opinar sobre el diseño.
- [ ] Correctness revisado primero: ¿funciona en todos los casos relevantes, no solo el feliz?
- [ ] Seguridad revisada: validación de input, autorización, manejo de secretos.
- [ ] El diseño es proporcional al problema (ni sobre-ingeniería ni atajos riesgosos).
- [ ] Los tests incluidos realmente verifican el cambio (no solo están presentes).
- [ ] Cada hallazgo está clasificado como bloqueante o sugerencia.
- [ ] Hay un veredicto final explícito: aprobar / cambios menores / cambios bloqueantes.
